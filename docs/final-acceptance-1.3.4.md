# 混合随机播放器 1.3.4 最终验收总结

日期：2026-11-17。状态：**本地验收版，未提交、未推送、未发布。**

结论：可以交给作者进行实际体验。已覆盖本轮要求的真实分 P 衔接、非活动标签页持续播放、多标签页操作与恢复路径；普通浏览器 hidden／最小化节流、真实冻结不能在本轮 ego lite 环境中等同验收，保留边界说明。

## 2. 本轮发现并修复的问题

### 分 P 被当作单 P，跳过后续内容

**用户现在怎么做 →** 把分 P 视频加入混合队列，让 P1 播完。

**问题 →** 1.3.1 实测在一个 2 P 视频结束 P1 后跳到另一个 BV。诊断版的只含计数探针显示：页面环境能看到 2 P，而用户脚本环境拿到的页数为 null。原代码把未知数量默认为 1，提前切换队列。

**改法 →** 从视频信息接口确认分 P 数量，不再依赖沙箱不可见的页面全局变量；同一 BV 按 P1→P2→…接续，最后一 P 后才切队列。元数据加载失败时不猜单 P，保留当前项，提供“重试分 P 信息”与手动下一首。

**可能影响 →** 每个播放文档需读取视频分 P 信息。接口失败会暂停自动接续，而非静默跳过；手动下一首仍切到队列下一视频。未声称网络或性能提升。

**验证 →** 真实 2 P 视频 P1→P2；P2 约 348 秒从头实际播放到结束，再进入预先记录的下一 BV。另一个真实 3 P 视频逐段进入 P1、P2、P3，作为队列末项时 P3 结束停留在原视频，显示“本轮播放结束”。诊断代码与临时存储探针已清理。

### 同一队列视频的副本同时播放

**用户现在怎么做 →** 在另一个标签页直接打开正在播放的队列视频。

**问题 →** 1.3.3 的控制页仲裁没有拦住副本的原生自动播放，真实检查两页 HTMLVideoElement 均为 paused=false。实际控制页未被替换，排除“重复领取所有权”；不是图标误报。

**改法 →** 对当前队列视频的播放事件和已开始播放状态进行所有权检查。活跃播放页存在时，副本暂停并提示通过面板控制原播放页；所有权已过期时可接管。

**可能影响 →** 当前队列视频的重复标签页不能同时播放；不会遍历或关闭用户其他标签页，也不把队列以外的所有 B站视频统一暂停。脚本加载前极短的原生起播时间不作零重叠保证。

**验证 →** 修复前真实两页同时播放；修复后副本 paused=true、原播放页 paused=false。新增真实调用路径的回归测试，先失败再通过。

## 3. 最终验收矩阵

| 场景 | 结果 | 方法／边界 |
| --- | --- | --- |
| 2 P：P1→P2 | 通过 | 同 BV、p=2、媒体实际播放；P1 seek 到末尾后等待实际 ended |
| 2 P：最后一 P→下一 BV | 通过 | P2 约 348 秒完整实播，地址与活动队列项均匹配预期下一 BV |
| 3 P：P1→P2→P3 | 通过 | 各 P 均确认已起播，再 seek 到末尾等待真实 ended |
| 队列末项最后一 P 后停止 | 通过 | 停在 P3，ended=true、paused=true，未跳推荐视频 |
| 分 P 切换后的窗口 | 通过 | 各段保留 600×700，123 项队列保留 |
| 非活动标签页持续播放 | 通过有限场景 | 留在其他标签页操作期间持续播放，97 个一秒样本无暂停；该环境始终报告 visible |
| hidden／最小化后的后台限流 | **未能等效验收** | 非活动页采样 hidden 次数为 0，不能冒充普通桌面浏览器后台行为 |
| 强制冻结后的真实恢复 | **未能有效制造冻结** | CDP frozen 后 4.5 秒探针仍计时 18 次；此前接管超时不是有效“冻结页失联”复现 |
| 控制页过期后的接管 | 逻辑回归通过 | 模拟所有权时间过期，浏览页接管并暂停旧页；不等同真实系统休眠测试 |
| 两个浏览页同时加入测试收藏夹 | 通过 | 两页均显示 123 项、唯一 BV 123；新增 0、合并 123、过滤失效 6 |
| 浏览页一暂停、浏览页二恢复 | 通过 | 检查播放页实际 media.paused，浏览页不跳转 |
| 重复打开当前队列视频 | 通过 | 副本暂停，唯一播放页继续 |
| 远程移出非当前条目 | 通过 | 另一页同步 122 项，原浏览条目锚点保留，播放暂停状态不变 |
| 从另一页撤销移除 | 通过 | 两页恢复 123 项，不修改 B站收藏 |
| 关闭播放页后接管 | 通过 | 关闭代理创建的播放页后，浏览页第一次点击即进入当前队列视频并播放 |
| DOM 回归 | 11/11 | 删除、撤销、原序／打乱、去重来源、分页失败重试、设置返回、重置范围、文本转义 |
| 播放回归 | 9/9 | 分 P、元数据失败重试、末项停止、幂等切歌、跨页控制、副本拦截、过期接管 |
| 语法与文档 | 通过 | Node 语法检查、diff 空白检查、相对链接检查 |

早期分 P 自动化步骤曾在新页起播处理尚未完成时直接 seek，导致测试超时。最终用新文档稳定、正确 P 值、媒体实际播放三者共同作为前置条件重新执行；没有把超时当作通过。

## 4. 自动化回归如何复跑

在播放器仓库目录执行：

```powershell
node --check bilibili-mixed-random-player.user.js
node tools/playback-regression.cjs
node tools/review-server.cjs
```

播放回归预期 9 项通过。最后一条启动本地合成界面；浏览器打开 `http://127.0.0.1:8765/?fid=100`，控制台执行 `await runPlayerRegression()`，预期 11 个 pass=true。再次执行前刷新页面。

播放回归运行实际脚本，模拟 DOM、GM 存储与媒体；刻意不提供页面全局变量，以覆盖脚本沙箱导致的分 P 缺陷。它不代替真实 B站网络、权限、视频或长期后台验收。

历史 `tools/review-repro.cjs` 固定读取 1.2 Git 提交，仍预期 2 通过、4 失败。它用于保留旧缺陷证据，不属于当前绿色验收套件。

## 5. 作者体验步骤

1. 在已更新的 ego lite 测试页面中直接体验，先核对设置页为 1.3.4；旧 B站标签页需刷新。
2. 若安装到另一浏览器，使用独立 `.user.js` 文件，通过 Tampermonkey 导入／编辑器保存。仅启用一份脚本；若管理器提示“重新安装将重置设置”，不要把它当作保留数据的普通更新。
3. 先用测试收藏夹：从两个收藏夹混合加入→打乱→调整窗口→切歌；随后试分 P、另一标签页暂停／恢复、移出与撤销。
4. 可以重点补充普通浏览器最小化、锁屏、系统睡眠唤醒后的体验。这些尚未获得本轮环境的有效验收证据。

## 6. 保留边界

- 不保证无缝音频衔接；切歌／切 P 会加载页面。
- 不把从头起播、视频加载成功、自动播放授权视作所有账号和浏览器均可用。
- 不保证多页同时写共享队列的原子事务；两页同时导入同一测试收藏夹已测，不代表任意删除／排序竞争组合均已覆盖。
- 没有连续数小时挂机、系统睡眠／唤醒、全部缩放比例与全部异常视频类型的结论。
- 测试过程中使用的本地版本 1.3.2、1.3.3 均未发布；最终交付为 1.3.4。本轮没有远程发布或 Git 推送。
