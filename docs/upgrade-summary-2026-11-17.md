# 播放器调优与升级建议摘要

> 历史提案：以下保留实施前的判断。用户随后确认优先项与播放规则；实际交付及验收结果见 [1.3.1 升级记录](upgrade-validation-2026-11-17.md)。

日期：2026-11-17。对象：当前 1.2 播放器。性质：供作者审阅的建议，尚未实施，也不是需求定稿。

## 结论

建议将下一轮升级定位为：**把多个收藏夹混在一起听时，播放、队列和窗口都能可靠地接续；再用一个轻量设置页容纳必要偏好。**

设置界面值得新增。此前“不建议现在新增设置中心”的判断偏保守：结合这次明确提出的窗口偏好和源码对照，集中设置已有充分用途。但记住窗口、避免误删、正确反馈失败属于默认行为，应修好，不能全部变成让用户自行排错的开关。

本轮只形成建议，播放器和提示词助手的产品源码均未修改；此前 README 改动保持原状。

## 1. 当前实际使用流程

1. **收集内容**：打开具体收藏夹 → 展开音乐球 → 加入当前收藏夹。脚本分页读取，按标题过滤“已失效”，把结果追加到原序和当前队列。它不是持续同步收藏夹，也没有去重。
2. **混合与排序**：到其他收藏夹继续加入 → 按加入顺序播放，或点击智能打乱。随机是一次洗牌；当前项置顶，其余条目重新排列，并不是每播完一首重新抽签。
3. **播放与切歌**：点条目、上一首、下一首，或结尾自动连播 → 修改当前索引 → 跳转完整视频页面。**不是在同一个脚本窗口中更换音源**，每次都要重新初始化脚本与窗口。所有这些跳转都带从头播放参数。
4. **边听边浏览**：面板控制网页 video，每 500ms 检查播放状态；状态变化会保存并重绘整个队列，随后滚向当前项。于是暂停也可能打断用户正在浏览的列表位置。
5. **悬浮使用**：可拖球、拖顶栏、右下角原生缩放、收起与快速双击顶栏收起。现在收起时将球放到收起按钮中心，展开时反推窗口位置并做边界夹取；**不是提示词助手那种按可用空间选择展开方向的完整锚点模型**。
6. **长期记忆**：`BCP_UI` 保存尺寸、球位置、窗口位置、主题和收起状态；`BCP_PLAY` 保存两份队列、当前索引、播放标记和全局来源。多个 B站标签页共享这些记录，没有明确的控制页归属。

用户核心任务是“把多个收藏夹放在一起听，同时还能整理和查找”，不是管理一套内容编辑工作台。界面应始终围绕正在播放、下一条、混合来源和队列操作组织。

## 2. 窗口变小：从用户反馈升级为真实复现

本轮经 ego lite 官方 API 在已安装脚本的真实 B站页面观察到：

| 场景 | 结果 |
| --- | --- |
| 收藏夹页点下一首进入视频页 | 窗口从约 417×617 变为 320×400 |
| 将视频页窗口设为 620×700 后普通刷新 | 本次保留了 620×700 |
| 再点击下一首 | 又变为 320×400 |

620×700 通过测试用 DOM 尺寸设置进入原脚本的 ResizeObserver 保存链路，不是一次鼠标拖拽验收。这里只确认手动切歌的异常；自动连播使用同一个跳转函数，但尚未据此声称自然播完也已实测。

**已经确认：保存／恢复能力存在，但切歌路径会失去选定尺寸。尚未完全确认：是哪一个写入者、哪个时机最终覆盖了值。** 观察到收藏夹页和视频页盒模型不同；尺寸观察器无条件把 contentRect 保存到共享 UI 状态。零尺寸写入、尺寸口径变化、其他页面写回需要继续区分，不能直接把其中一个写成唯一根因。本轮附加尺寸探针只记录尺寸，已移除；未读取凭据。

候选修复：统一尺寸口径，保存用户明确选择的目标尺寸；临时视口适配不覆盖目标尺寸；忽略无效测量；按字段更新布局，防止旧页面写回整份状态。切歌的新页面读取同一份有效布局。建议检查顶层页面／iframe 运行范围，因为播放器没有提示词助手的顶层窗口与重复注入保护。

验收：拖大→手动下一首→上一首→自然播完自动下一首→收起状态下切歌→刷新，逐次检查尺寸、位置、主题和收起状态；同时测试双标签页、动森边框、窄屏临时缩小后恢复。容差应只覆盖像素取整，不能接受回到最小尺寸。

## 3. 建议调优项，按实施顺序排列

| 用户现在怎么做 | 问题或机会 | 候选改法 | 可能影响 | 怎么验证 |
| --- | --- | --- | --- | --- |
| 调好大小后切歌 | 已真实复现窗口回到 320×400 | **第一优先：可靠保存与恢复窗口**；目标尺寸、实际尺寸分离，明确跨页写入归属 | 旧数据迁移、主题边框、多页状态 | 按上一节完整切歌矩阵验证 |
| 拖球、展开、拖窗口、再收起 | 球与窗口虽然有关联，但靠按钮中心反推；边缘夹取会使位置关系变化，视口缩小已有越界复现 | **统一锚点绑定**：球决定展开位置，自动选择能放下窗口的方向；窗口移动后球随同一锚点更新；边缘优先保证控件可达 | 展开手感会变化，需保留已有拖动习惯；空间不足不应永久缩小偏好 | 四角、四边、拖后收起、视口变化、跨页还原；拖动结束不误触展开 |
| 翻队列时暂停、切设置 | 暂停会抢滚动；未来设置返回也可能丢现场 | **保持浏览现场**：播放状态局部更新，列表保留滚动；增加“定位当前播放”；设置返回恢复进入前位置 | 换序、移除后需按条目锚点恢复，不能恢复旧播放进度或队列快照 | 长队列滚动→暂停／设置／主题／收起→返回；播放事实与浏览位置分别检查 |
| 从列表移出条目，再恢复原序 | 隔离测试已复现被删项复活、相邻项错删 | **先修双队列一致性**；条目身份稳定；移除文案明确只影响混合队列，可提供短暂撤销 | 重复 BV、当前项删除、跨标签页撤销冲突 | 首／中／尾／当前项、重复项、洗牌后删除；恢复与打乱不复活 |
| 加入收藏夹、失败后再次加入 | 部分页失败仍报成功；重复点击会重复追加，加载文案还可能被周期刷新覆盖 | **完整／部分／失败分别反馈**，显示读取数量与重试入口；重试避免重复追加 | 是否提交部分结果、旧来源与新结果如何合并需定规则 | 空夹、权限、断网、第二页失败、重复加入和中途切页 |
| 视频结束或无法开始播放 | 当前以共享布尔标记和轮询控制，未处理 play Promise 失败；缺少明确恢复路径 | **让播放反馈依据实际结果**；媒体事件为主、幂等切歌，提供重试／手动跳过；不默认无限自动跳过 | 分 P、自动播放限制、跨页加载、多页争用 | 自然结束、尾部暂停、加载慢、拒播、失效视频、分 P、多标签页 |
| 从多个来源找某首视频 | 只有全局来源，长队列缺少查找；来源不等于每项所属收藏夹 | **轻量搜索与来源辨认**；筛选只影响浏览，不静默改待播顺序；每项保留来源关系 | 去重后可能对应多个来源，需要条目模型支持 | 两夹有交集，筛选前后当前项与下一项不变，清筛选恢复浏览位置 |
| 阅读标题、频繁调节窗口 | 字号固定、动作同排拥挤，原生缩放只有右下角较难触达 | **轻量设置页＋控件适配**，必要时扩展边角缩放；保留三主题的色彩、圆角和质感 | 大字号提高行高；缩放触区不能遮住原生网页 | 三主题、长标题、大字号、键盘、小窗口；不据此宣称性能提升 |

前六项解决核心体验，第七、八项再完善日常使用。搜索是候选新增能力，不能写成当前已有。

## 4. 设置页建议：小而实用

建议顶部只增加一个有名称提示的设置入口。设置在面板内部打开，保留底部正在播放区和播放控制；返回按钮回到原队列位置。设置即时生效并保存，不为主题、字号等偏好增加“保存草稿”。

首版可分为“外观与窗口”“播放与队列”两组，底部放版本和帮助。以下是建议默认值，尚未实施：

| 设置／操作 | 建议默认与用途 | 范围 |
| --- | --- | --- |
| 主题 | 沿用用户现有选择；保留暗色、亮色、动森 | 已有能力集中展示，可保留快捷主题菜单 |
| 字号 | 默认贴近现有尺寸，提供有限的可读范围及恢复默认 | 新增偏好；具体上下限需实测 |
| 列表密度 | 标准／紧凑，默认标准 | 调间距与次要信息，不引入四种布局 |
| 悬浮球大小 | 默认保留当前 52px；有限范围调节 | 球变大后重新计算锚点与边界 |
| 收起方式 | 收起按钮保留；双击顶栏默认延续当前行为；点击外部收起默认关闭 | 外部收起需排除拖动、缩放和弹窗 |
| 减少透明效果 | 默认保留现有主题质感；开启后提高实色背景覆盖 | 可读性选项，不作未经测量的性能承诺 |
| 恢复窗口位置与大小 | 明确按钮，文案说明重置范围 | 不清队列、不改收藏；与恢复其他偏好分开 |
| 自动播放下一首 | 默认开启，延续主要用途 | 用户可以只听当前项；失败处理不能无限跳歌 |
| 切换视频起点 | 自动下一首建议从头；手动选择的恢复历史规则另定 | 不覆盖用户主动拖动进度 |
| 重复视频处理 | 建议默认同 BV 合并、保留多来源，但需作者确认 | 会改变混合队列语义，不能悄悄启用 |
| 一轮结束行为 | 默认播完停止，延续现状；是否提供队列循环需确认 | 不直接扩展多个复杂随机模式 |

**不建议做成开关的内容**：正确记住窗口大小、暂停不抢滚动、删除不出错、失败不报成功、设置返回不丢现场、清空不删除 B站收藏。这些应是稳定的基础行为。

## 5. 提示词助手具体借鉴什么

| 提示词助手中的机制 | 播放器可以借鉴的部分 | 需要调整或舍弃的部分 |
| --- | --- | --- |
| `anchor / panelSize / geometry / direction` 分开管理；`anchoredRect / launcherFromRect` 互相换算 | 同一个锚点解释展开、移动、收起；保留用户目标尺寸与视口适配尺寸的区别 | 不复制助手默认尺寸与样式；跨页和多页写入要重新设计 |
| pointer 拖动、移动阈值、结束时保存；四边四角缩放 | 避免拖动误点击，减少无意状态写入，更容易调整大小 | 播放器是否需要最大化暂列后续，不为相似外观硬加控制点 |
| 设置即时应用、字段合并、重置入口 | 集中必要偏好；修改字号不重置位置，修改主题不覆盖新队列 | 不搬网站名单、坚果云、备份迁移体系 |
| 页面快照与返回恢复滚动 | 未来“队列→设置→队列”保留查找与浏览现场 | 不需要 40 层导航栈；不能用旧快照恢复播放状态 |
| 操作反馈和撤销 | 让载入、移除、失败后的下一步可理解 | 播放命令需由实际媒体结果确认，不可只借用成功提示外观 |
| Shadow DOM、顶层页面保护 | 评估隔离宿主 CSS、避免 iframe 重复实例，稳定盒模型与样式 | 属于内部实现改进，不对用户增加配置；仍需验证媒体访问与管理器兼容 |

没有必要加入草稿、变量编辑、AI 工具、云同步、四种排列或提示词分组系统。播放器应继续是围绕混合队列和网页播放的小工具。

## 6. 实施前真正需要定下的规则

建议只集中确认四组，不把每个小细节都交给用户：

1. **重复与来源**：同一视频在多个收藏夹中是否只播一次？建议去重并保留多个来源。
2. **移除当前项**：建议不突然打断当前音视频；播完后接哪一项、还是停止连播，需要明确。
3. **多标签页**：建议只让一个页面负责播放，其他页面用于浏览和加队列；切换控制页需明确，不能互相抢歌。
4. **起播与循环**：自动下一首从头；手动选择是否恢复历史、队列末尾是否循环，作为明确偏好讨论。

窗口大小记忆、锚点一致性、浏览位置和错误反馈可以先进入修复方案，不依赖上述规则全部确认。

## 依据与验证边界

- 播放器：`bilibili-mixed-random-player.user.js` 的状态存储、窗口 CSS、`initUI`、ResizeObserver、拖动／收起／展开、`fetchFav`、队列增删换序、`jumpToCurrent` 与结尾轮询。
- 提示词助手：只读核对 `src/app.js` 的布局、拖动、设置与视口适配；`src/core.cjs` 的窗口／锚点计算；`src/navigation.js` 的返回与字号设置。未修改提示词助手。
- 既有问题及上一轮验收：[交互核对记录](interaction-review-2026-11-17.md)。本摘要补充了切歌窗口变小的真实复现，并将轻量设置页列为建议新增能力。
- 本轮未完成自动连播、完整跨页尺寸根因、所有主题／显示缩放及多标签页仲裁验收。建议不是已交付功能，也没有性能提升结论。
