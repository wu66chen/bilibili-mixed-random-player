证据分为三层：

- **源码核对**：阅读完整交互实现，引用下方函数与行号。行号指本次未修改的 1.2 脚本。
- **隔离复现**：Node 24.19.0 执行原脚本，替换 DOM、GM 存储、计时器、网络和 video；内置浏览器运行原脚本的真实 DOM，使用合成收藏夹。能证明相应逻辑和界面行为，不能证明真实 B站、Tampermonkey 跨页存储或视频播放。
- **真实环境**：Windows 上用户指定的 ego (lite) 配置，用户完成脚本安装与运行权限设置后，经官方 ego-browser API 在独立任务空间验收。首次读取、首次播放、暂停恢复、原生暂停同步、打乱和暗色→动森→暗色、收起展开已实测；同时复现了暂停抢滚动与小视口越界。未读取 Cookie、密码或授权头，未修改远端收藏；文档不记录账号、私人收藏清单或测试收藏夹地址。

## 已有但需要改进的行为

每一项均按“用户现在怎么做 → 问题或机会 → 候选改法 → 可能影响 → 怎么验证”展开。优先级是本次评审顺序，不引入其他仓库的标签体系。

| 优先级／证据 | 用户现在怎么做 | 遇到什么问题或机会 | 候选改法 | 可能影响 | 怎么验证 |
| --- | --- | --- | --- | --- | --- |
| 高；Node 与隔离浏览器复现 | 移出第二项，再恢复原序或打乱 | 被删项复活，下一项反而从原序丢失；删末项也会复活 | 删除前保存被删条目，再从两份队列移除对应同一条目；重复视频需稳定条目身份 | 涉及原序、当前索引、重复项及持久化兼容；不能只改视觉 | A/B/C 删除 B→恢复应为 A/C；删 C→恢复应为 A/B；打乱后删、删当前项、重复 BV 另测 |
| 高；Node 与隔离浏览器复现 | 加入多页收藏夹 | 第二页网络失败仍显示“载入成功”，只加入第一页；空夹、权限、网络错误都可能被归因于私密 | 返回完整／部分／失败状态、已读页数和数量；明确保留已有队列，给重试入口 | 重试不能把第一页重复追加；需确认部分内容提交策略 | 第 1 页成功第 2 页失败、API 非零、空夹、超过 100 页，核对提示及队列；恢复网络后重试 |
| 高；Node 与真实网页复现 | 长队列滚到后面，再暂停或在原生视频上暂停 | `savePlayState` 总重绘列表，随后自动 scrollIntoView 当前项；真实暂停时 scrollTop 从 8556.667 变为 90（仍在平滑滚动），用户浏览位置被夺走 | 播放状态更新与队列渲染分开；只在主动定位当前项或明确切歌时滚动 | 删除、换序后应定义视觉锚点；不能恢复旧快照而倒退播放状态 | 长队列中记录可见条目，暂停、收起、主题、远端状态变更后比较；切歌定位单独验收 |
| 高；源码风险，未复现真实拒播 | 点击播放或选视频 | `video.play()` 未 await/catch，先写 isPlaying；切页也先写播放中；按钮状态不是实际成功证明 | 区分准备／播放／暂停／失败，依据媒体事件与 Promise 更新；失败提供网页播放和重试路径 | 不要由其他标签页覆盖正在播放页的真实状态；避免错误后自动连跳 | 自动播放拒绝、视频未就绪、video 元素被替换、已删除／无权限视频，观察声音与进度而非仅图标 |
| 高；源码与隔离逻辑 | 移除当前项或清空队列 | 脚本变成未播放，网页视频继续；“清空”还通过共享存储影响其他标签页 | 文案明确“移出混合队列／清空混合队列，不删除 B站收藏”；说明视频与后续连播影响；低成本撤销可候选 | 当前项移除后的连播规则必须先确认；撤销不能覆盖其他标签页的新队列 | 网页 video、队列、原序、当前索引、其他标签页及远端收藏数量分别核对 |
| 中高；真实网页模拟视口复现 | 浏览器缩小、拖到边缘、刷新后展开 | 视口从 2548×1270 模拟为 600×400 时，窗口仍在 x≈1139、y≈332，宽≈419、高≈619，超出视口；恢复视口后重新可见。源码没有视口 resize 监听，最小 320×400 可大于视口 | 视口变化时约束球和窗口；尺寸上限按可见范围；保留入口与收起按钮连续性 | 原生 resize、主题边框与旧位置迁移要一起测 | 四角拖动、收起展开、200% 缩放、短屏、刷新；主要控件始终触达 |

| 中；真实 DOM 已观察到换行 | 默认 420px 宽面板使用整排操作 | 多个按钮挤在一排，字词分行；不宜先叠加字号选项 | 保留主题，按加入／队列整理／来源与主题／清空组织操作；允许按组换行 | 更大字号或动森边框可能增加高度；不得遮住播放控制 | 三主题、长标题、320/420px 面板宽度和放大后核对；不据此宣称性能提升 |

## 确实缺失、值得新增的候选

1. **请求结果与恢复入口**：已有读取按钮和 alert，但没有部分完成、失败原因与可重试状态。优先于新布局。
2. **“定位当前播放”显式操作**：现有强制自动滚动可改成用户主动定位。它与浏览位置保留组成一项完整改进，而不是新增多级页面。
3. **可理解的移除范围与短暂撤销**：现有移出按钮没有撤销；加入撤销前需处理共享队列的版本变化。
4. **每项来源关系**：当前只存全局 folders，条目只有 bvid/title/cover。若要显示某条来自哪些收藏夹、按来源移除或去重后保留来源，需要新增模型；不是补一个标签即可。

不建议现在新增设置中心、四种布局、草稿、组合方案、云同步或 AI。当前没有筛选页、设置页或详情路由，不能照搬“逐级返回”架构；眼下应保护已有单列表的浏览位置。

## 需要用户确认的规则

| 决策 | 1.2 当前实现 | 建议讨论的候选，尚未定稿 |
| --- | --- | --- |
| 重复视频 | concat 直接追加，同夹重复加入也重复；folders 仅按 fid 去重 | 默认 BV 去重并保留多来源，或保留多次播放条目 |
| 随机与一轮结束 | 一次洗牌后顺序播放；当前项置顶；最后一项结束不显式循环 | 保留一次洗牌语义，是否增加循环另议 |
| 删除当前项 | 索引变 -1，isPlaying=false，但不暂停网页 | 继续播完并停止连播，或继续播完接下一条；不默认强制跳歌 |
| 清空 | 清原序、当前队列、来源和索引；不暂停网页 | 明确保留当前网页播放；是否同时停止连播需文案承诺 |
| 部分读取失败 | 已读内容直接追加且报成功 | 整次不提交后重试，或明确保留部分并只重试未完成页 |
| 多标签页 | 共用 BCP_PLAY，远端变更重绘；没有控制页仲裁 | 单一播放页 + 其他页浏览／加队列，或每页独立会话 |
| 从头播放 | 所有 jumpToCurrent 都带 t=0/bcp_start=1，包含手动选择、上一首和下一首 | 自动下一首从头；手动选择是否恢复 B站历史；不应覆盖主动拖进度 |
| 持续记忆 | GM 保存队列和窗口；不保存视频 currentTime 或列表 scrollTop | 跨页保存队列与偏好；进度、临时浏览位置的保存期限另定 |

## 可重复验证

在仓库根目录执行（本次 Node 24.19.0）：

```powershell
node --check bilibili-mixed-random-player.user.js
node tools/review-repro.cjs
node tools/review-server.cjs
```

前两个是语法检查和逻辑复现。第三个仅启动 `127.0.0.1:8765` 的隔离页面，打开终端输出的地址；用 Ctrl+C 结束。没有 npm 安装步骤。

基线复现结果为 **2 通过、4 失败，退出码 1**：两种删除恢复失败、部分读取误报成功、暂停触发滚动失败。此工具故意保留失败，用于下一轮修复前后比较，不是绿色验收套件。

隔离浏览器步骤：

1. 30 个合成条目，移除 02，单独点恢复原序；可见 02 重新出现、03 缺失。
2. 选择“第一页成功，第二页失败”，点加入；实际弹出“载入成功！加入 1 个视频”。
3. 暗色切动森、收起再展开，核对队列仍在。

夹具拦截 fetch，使用内存 GM 替身和数据图片，不读写真实收藏或已有脚本存储。**不要在夹具点击视频／上一首／下一首**：原脚本的页面导航仍保留。夹具没有真实视频，不能测试播放成功。夹具样式限定在 main，避免污染脚本按钮。

删除诊断的候选解释：① splice 后读取已变化的下标；② 两数组共享；③ 恢复逻辑错误。源码 647–649 明确先 splice，再以 `currentList[idx]` 找原序；独立克隆数组的 Node 夹具仍失败，真实 DOM 同样失败。恢复只是复制 originalList，故主要原因定位在删除时取错身份。下一轮修复须覆盖重复 BV，不能只通过 A/B/C 就宣称完成。
