## 已确认的规则

用户集中回复 A：同 BV 合并并保留多来源；移出当前项后播完接原下一项；单一播放页、其他页浏览及加队列；手动／自动切歌从头，一轮结束停止。

## 实际测试与证据边界

### 真实 B站 + 已安装用户脚本

经 ego lite 官方 CLI/API 操作，无桌面鼠标接管。通过管理器更新 1.2→本地候选版，后更新到 1.3.1，避免同版本“重新安装”提示的设置重置路径。

- 实际鼠标拖拽将窗口从原尺寸调为 600×700；手动切歌后仍为 600×700，队列 123，视频播放进度约 0.35 秒。
- 暂停前后队列 scrollTop 均为 900。
- 动森主题背景计算值 `rgb(248, 248, 240)`，字号变化保留条目锚点；恢复暗色、13px。
- 删除当前测试队列项后，视频仍未暂停；等待它实际 ended 后，按预先记录的下一条 BV 验证地址与活动条目都一致；窗口仍 600×700。随后撤销，队列恢复 123。
- 选择队列末项，拖到末尾，让媒体实际 ended；之后观察 2.5 秒，地址仍为该视频、ended 与 paused 均为 true，显示“本轮播放结束”。
- 最后恢复测试队列首项并暂停；普通刷新后尺寸 600×700、123 项、暗色主题仍在。
- 最终工作副本重跑 11 项 DOM 回归全部通过；合成页面拖球到四个角落后展开均在视口内，600×400 下窗口为 420×384、底部播放键可见，保存宽度仍为 420。

末尾测试用了 seek 到 duration−2 秒，然后等待真实播放结束。没有伪造 ended 事件，也没有据此宣称完整时长、长期后台播放都已验收。

### 发现后纠正的验收方法

候选版曾仅以 URL 变化判断自动连播成功，进一步按 BV 检查时发现 B站跳到了推荐视频。该结果不作为队列连播通过证据。最终版本以**预期下一条 BV + 当前活动条目 + 媒体实际状态**共同确认。

窗口变小的历史异常已实测，但不能把 iframe、盒模型或某个写入时机写成唯一根因：本次修复明确移除了无条件测量写回路径，并用真实切歌回归确认行为；未记录所有旧版写入者的完整追踪。

### 合成数据 DOM 回归

`tools/review-server.cjs` 提供本机隔离界面，`tools/browser-regression.js` 使用真实 DOM 与用户操作处理器。11 项通过：

1. 中间项删除不复活、不误删下一项。
2. 末项删除后打乱／恢复不复活。
3. 撤销只恢复最近移出的项。
4. 删除当前项保留播放项与原下一项。
5. 再删待播项会衔接后续有效项。
6. 设置返回保留浏览位置。
7. 分页失败明确报告中断。
8. 重试不重复加入。
9. 两个来源同 BV 合并来源。
10. 重置窗口不改队列。
11. API 标题作为文本渲染，不解释为 HTML。

这不是 Tampermonkey 权限、真实网络接口或真实视频事件的替代验收。历史 `review-repro.cjs` 固定读取 1.2 提交，仍保留 2 通过、4 失败的缺陷基线。
